# 环信 WebDemo 自动化测试专属 Prompt（Playwright 适配）
## 一、页面基础信息（必看）
1.  核心页面：2个核心页面（与 PO 模式对应，方便元素定位封装）
    - 页面1：聊天室列表页（对应你之前的「页面1」）
    - 页面2：聊天室内页（进入房间后的操作页面）
2.  浏览器兼容：支持 Chrome、Edge 浏览器，自动适配分辨率，无需手动设置
3.  操作前提：已完成登录（前置条件，由 fixture 或用例前置处理）
4.  聊天室自动化默认前提：先通过服务端 API 创建测试用户与聊天室，再执行 UI 流程

### 4. 数据生成要求
- 用户名、昵称、聊天室名称、roomid 必须唯一
- `roomid` 仅允许小写字母和数字
- 创建成功后，UI 用例要基于新建资源执行，不可重新退回人工数据

### 5. 数据使用要求
- 页面1 列表页：需优先搜索或定位接口创建的聊天室

## 二、页面元素定位&操作规范（Playwright 专用）
### 1. 页面1：聊天室列表页（核心操作）
- 元素定位优先用「get_by_role」「get_by_text」，禁止用 CSS/XPATH 硬定位
- 刷新按钮：get_by_role("button", name="刷新")（对应列表页刷新功能）
- 搜索框：get_by_placeholder("请输入聊天室名称/ID 搜索")
- 加入按钮：get_by_role("button", name="加入")
- 详情按钮：get_by_role("button", name="查看详情")
- 页面切换：点击列表页聊天室名称，跳转至聊天室内页（页面2）

### 2. 页面2：聊天室内页（消息&权限操作）
- 消息输入框：get_by_placeholder("请输入消息内容")
- 发送按钮：get_by_role("button", name="发送")
- 图片上传按钮：get_by_role("button", name="上传图片")
- 文件上传按钮：get_by_role("button", name="上传文件")
- 成员管理入口：get_by_role("button", name="成员管理")
- 禁言操作按钮：get_by_role("button", name="禁言")
- 权限设置按钮：get_by_role("button", name="权限设置")

### 3. 消息收发&文件上传规范
- 文本消息：输入内容后点击「发送」，断言消息出现在消息列表
- 图片消息：点击「上传图片」，选择本地文件，断言图片发送成功
- 文件消息：点击「上传文件」，选择任意格式文件（文档、压缩包等），断言文件上传成功
- 语音/视频消息：录制/上传后，断言播放正常、时长显示正确

## 三、消息收发全类型操作规范（适配你的业务）
1.  文本消息：输入内容 → 点击发送 → 断言消息出现在消息列表，显示发送人、发送时间
2.  图片消息：点击上传图片 → 选择本地图片 → 断言图片显示正常、可预览
3.  语音消息：点击「录制语音」→ 结束录制 → 发送 → 断言语音可播放、时长正确
4.  透传消息：发送后断言回调正常，消息状态显示「已发送/已送达」
5.  异常场景：无权限发送、网络中断时，断言提示信息正确（如「发送失败，请检查网络」）

## 四、多页面联动&断言要求
1.  列表页 → 内页切换：点击列表页聊天室名称，自动跳转至内页，无强制等待
2.  消息发送断言：发送后1秒内（Playwright 自动等待），消息列表显示该条消息，状态为「已发送」
3.  权限校验：无权限发送消息/操作时，断言「无权限」提示正常显示
4.  失败处理：操作失败时，自动截图留存，便于排查问题
5.  服务端 → UI 联动：接口创建聊天室后，UI 列表中必须可定位到该聊天室
6.  服务端 → UI 联动：接口创建的 owner / members 在 UI 中展示出的加入状态必须正确

## 五、与 superpowers、speckit 配合要求
1.  严格遵循 PO 模式，页面元素全部封装到对应 page 类（列表页、内页分开）
2.  不使用 time.sleep()，全部用 Playwright 自动等待机制
3.  消息发送、成员管理、禁言等操作，均需做 UI 可视化校验（断言页面显示）
4.  生成代码时，需包含页面元素封装、fixture、测试数据创建逻辑、用例编写、报告配置，可直接运行
5.  新增聊天室自动化时，优先复用接口创建的动态数据，不继续放大人工环境依赖
